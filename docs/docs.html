Setup

Choose the no-build CDN route for a static page or prototype, or compile Windform with Tailwind for production optimization. Bootstrap 5.3.8 remains the sole component-interaction runtime and its bundle already includes Popper.

Fast start: CDN only

No Node.js, npm, or bundler is required. Add Windform’s generated stylesheet, Tailwind’s browser CDN, and Bootstrap’s bundle to any HTML document. You can also open the standalone CDN starter and copy its source.

<link rel="stylesheet" href="https://md-riaz.github.io/Windform/assets/windform.css">
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>

<style type="text/tailwindcss">
  @theme {
    --color-background: hsl(var(--background));
    --color-foreground: hsl(var(--foreground));
    --color-card: hsl(var(--card));
    --color-card-foreground: hsl(var(--card-foreground));
    --color-primary: hsl(var(--primary));
    --color-primary-foreground: hsl(var(--primary-foreground));
    --color-secondary: hsl(var(--secondary));
    --color-secondary-foreground: hsl(var(--secondary-foreground));
    --color-muted: hsl(var(--muted));
    --color-muted-foreground: hsl(var(--muted-foreground));
    --color-accent: hsl(var(--accent));
    --color-accent-foreground: hsl(var(--accent-foreground));
    --color-border: hsl(var(--border));
    --color-input: hsl(var(--input));
    --color-ring: hsl(var(--ring));
    --radius-sm: calc(var(--radius) - 4px);
    --radius-md: calc(var(--radius) - 2px);
    --radius-lg: var(--radius);
  }
</style>

<script defer src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"></script>

The @theme mapping is required for new semantic Tailwind utilities such as bg-primary and text-muted-foreground. Use this route for demos, learning, and simple static pages; pin CDN versions and choose the build path for the smallest production CSS, strict content-security policies, and reproducible/offline deployments.

Choose an authoring path

Tailwind-native: write semantic utilities such as bg-primary and text-foreground directly in markup.
Bootstrap-compatible: use documented Bootstrap selectors such as .btn and .modal; Windform maps them to the same tokens with @apply.

Production build: 1. Add Windform to Tailwind

Copy the source file into your project (for example resources/css/windform.css) and include it in tailwind.config.js so the compiler can see your component templates. 

// tailwind.config.js
module.exports = {
  content: [
    "./resources/views/**/*.blade.php",
    "./public/**/*.html",
  ],
  theme: { extend: {} },
  plugins: [],
};

// resources/css/app.css
@import "./windform.css";

2. Compile an optimized stylesheet

Run the Tailwind CLI, Vite, Mix, or your preferred build tool to generate the CSS that applies Windform’s utility recipes to your markup. 

npx tailwindcss -i ./resources/css/app.css -o ./public/build/windform.css --minify

3. Load the optimized stylesheet

Reference the CSS emitted by your build as the primary stylesheet for your project. Windform is designed to replace legacy Bootstrap styles with Tailwind utility classes, so you no longer need to ship Bootstrap’s CSS alongside it. The docs/assets/windform.css file that powers this site is a demo artifact, not a published distribution. 

<link rel="stylesheet" href="/build/windform.css">

4. Keep the Bootstrap bundle for interactivity

While Windform replaces the Bootstrap CSS layer, its interactive components still rely on Bootstrap’s JavaScript bundle. Ship bootstrap.bundle.min.js so data attributes, toggles, and other behaviours continue working—Bootstrap 5 no longer needs jQuery. 

<script defer src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"></script>

Component reference

Browse blocks

Browse the component gallery for supported Bootstrap-compatible markup and the blocks catalog for Tailwind-native layout snippets. See src/windform.css for the compatibility selectors.

Utilities like text-muted-foreground or bg-card are authored in Tailwind but compiled into the CSS your build emits. Layer them with your own utility classes for layout tweaks.

Bootstrap-compatible examples are labeled by their runtime contract. CSS-only recipes provide visuals only; they do not include selection, positioning, keyboard navigation, focus management, dragging, filtering, or data behavior.

Customising Windform

Rebuild the CSS

Duplicate tailwind.config.js, tweak colours or spacing, then run npm run build. Point the output to your project’s public directory (for example public/build/windform.css).

Extend tokens

Add custom CSS variables or override existing ones by layering a small stylesheet after Windform. Because everything compiles to CSS variables, you can change palettes without editing every component.

Maintain consistency

Commit the generated CSS your build produces alongside your project to keep deployments deterministic. Replace the file when new releases ship.

Dark mode ready

Add the dark class to the theme root to switch token palettes. The documentation toggle also stores data-theme as site metadata, but the CSS theme selector is .dark.

Keeping Windform updated

Because Windform is file-based, updates are as simple as pulling the latest src/windform.css, re-running your Tailwind build, and copying new snippets into your project.

For version control, commit the stylesheet to your repository so that deployments stay deterministic.
